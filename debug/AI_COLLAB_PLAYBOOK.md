# AI 协作手册（昇腾 vLLM / AFD 场景）

> 目的：把"跟 AI 来回猜"变成"一次给够上下文 + 每轮只回一个结论文件"。
> 用法：新会话开头贴 §1，每轮提问套 §2，要求 AI 按 §3 的格式产出，结果记到 §5。

---

## 1. 环境画像（写一次，每次会话开头贴）

```text
【模型】DeepSeek-V4-Flash, n_routed_experts=?, num_experts_per_tok=?, 量化=W4A8MXFP
【硬件】A5, 单机 8 卡, CANN=x.y, torch_npu=x.y, vllm-ascend commit=?, vLLM commit=?
【部署】AFD: 4A2F(CAMAsyncAFDConnector) / 混布: DP8 TP1 EP8
【基线】能跑通的配置：4 卡混布 EP4（同环境同量化同代码）
【目标】选型（6 卡该用哪种部署） 还是 归因（AFD 机制比混布强多少）
【通道】绿区 = 单向只读（只允许 git pull / 本地运行，禁止任何 push/上传/外发）；
        代码流入走 fork 的调试分支；结论流出走已批准文本通道，且先脱敏
【AI 能力】本会话有没有 shell？能不能 push？（没有 → 产物一律走 patch/脚本文件）
【AI 能力】本会话有没有 shell？能不能 push？（没有 → 产物一律走 patch/脚本文件）
```

**为什么值得**：本会话前 3 轮，"专家数/量化/AFD 配比/真实目标"都是靠猜或追问补上的；
这些信息 30 秒写完，能省掉 2~3 轮往返。

## 2. 提问模板（每轮）

```text
【现象】<一句话>
【首个错误】<完整 worker traceback 的前 15 行，含 op 名/设备/PID>
【与上次相比只差】<例如：只把 data-parallel-size 从 4 改成 8>
【已排除】<例如：开关图模式都复现>
【本次想要】<定位 / 给补丁 / 给判别实验>
```

三条纪律：

1. **一次只改一个变量**，并显式写明"只差什么"——本会话最关键的一条事实
   （"4 卡 OK、8 卡挂，只差卡数"）就是靠这个才收口的。
2. **不要贴整段日志**：先 grep 出结论行（`RESULT:`、`Moe comm method selected`、`ERR00100`）。
   多进程日志会交错，长日志还会被截断——本会话因此白跑过一轮。
3. **代码不要走对话**：pasted 代码容易被中转模型改写。走 patch/分支（见 §4）。

---

## 3. 要求 AI 的输出格式

* **结论分级**：`事实（日志直接证实）` / `推断（依据是什么）` / `待验证（怎么证伪）`。
  本会话里"量化不支持"那条就是我把推断说成了结论，用户追问后才修正。
* **每个方案附"生效前置条件"**：例如"静态 EPLB 表可用"的前提是 `expert_map_path` 非空，
  且录制需要 `dynamic_eplb=True` —— 漏了前置条件就会白跑（本会话踩过）。
* **产物要可执行**：patch + 一键 runbook + `--revert`，不要给散落的代码片段。
* **不确定就说不确定**，并给出**最省的判别实验**，而不是给一堆可能。

---

## 4. 代码与实验的流水线

```text
我(AI) 写文件 → 你侧 push_debug_branch.sh → 绿区 git fetch/checkout debug/xxx
      → run_matrix.sh（自动跑变体、收集、生成 report.txt）→ 回传 report.txt
      → run_matrix.sh --revert / git checkout main
```

约定：

* 一个实验 = 一个分支（`debug/<主题>`）+ 一个目录 + 一条命令 + 一个结论文件；
* 框架侧改动（vllm / vllm-ascend / afd-plugin）走同一分支，按
  `patches/<repo>/NNNN-*.patch` 分目录堆叠，`apply_all.sh` / `revert_all.sh` 管进管出；
* 调试分支**永远不开 PR 到上游**；正式修复另开干净分支（带测试 + `Signed-off-by`）；
* 危险命令（`pkill`/`rm`）默认关闭，需要时显式开。

## 5. 实验台账（每跑一组就记一行）

| 日期 | 配置差异 | 命令 | 结果 | 结论/下一步 |
|---|---|---|---|---|
| 09-23 | DP8 vs DP4 | `run_matrix.sh` | ALLTOALL 分支 MoeInitRoutingV3 失败 | 分支问题，非环境 |

作用：避免"这个上次试过了吗"的重复劳动，也方便把结论喂给下一轮会话。

---

## 6. 一页速查：最省时间的 6 个习惯

1. 开头贴**环境画像 + 目标**；
2. 一次**只改一个变量**，显式写明；
3. 日志先 **grep 出结论行**，别贴全文；
4. **代码走文件**，对话只传结论；
5. 要求 AI **标注证据级别**，并可追问"这条是事实还是推断"；
6. 每轮结束让 AI 产出一份**可粘贴的"当前事实清单 + 未决问题"**，下一轮开头带上（对抗上下文丢失）。

## 7. 代码搬运的硬规矩（经中转 LLM / 摆渡进绿区）

**合规红线（最高优先级）：绿区是单向只读区。**
绿区只允许 `git pull` / 本地 apply / 本地运行；
**禁止**从绿区 `git push`、上传、外发日志——那是信息违规。
所有"向 GitHub 写入"的动作只能发生在**可上外网的中转机**上。

原则：**代码走机器通道（单向流入），人只走结论（走已批准通道流出）。**

| 环节 | 坏做法 | 好做法 | 收益 |
|---|---|---|---|
| AI 出 | 输出 N 段代码片段让你手改 | 输出**一个自包含应用脚本/patch**：幂等、锚点校验、`--revert` | 传输面从 N 处降到 1 个文件 |
| 传 | 裸代码贴进中转 LLM | ①优先 git（分支/patch）；②只能文本时用 **base64 包裹**再贴；③落盘后立刻校验 | 消除"被改写/截断/自动补全"类故障 |
| 落 | 手工编辑多个文件 | `python3 apply_xxx.py --root <repo>`；先 `git diff` 复核；`--revert` 回退 | 不再需要逐个文件 `git restore` |
| 回 | 贴整段日志/截图 | runner 自动生成 ~20 行 `report.txt`，只回这一份 | 一轮往返拿全信息 |
| 沉淀 | 每轮从零 | 常驻 `debug/<主题>` 分支 + `patches/<repo>/` + 台账 | 可复用、可回退、可交接 |

**落地前必做的三道校验**（因为这个 AI 常常没有 shell，算不出校验和，
所以只能靠"落地处自检"）：

```bash
python3 -m py_compile apply_xxx.py        # 语法没被改坏
python3 apply_xxx.py --root . --check     # 锚点匹配（不写文件）
python3 apply_xxx.py --root . && git diff # 应用后肉眼扫差异块
```

**如果代码必须经中转 LLM**，给它这句指令，并要求它原样输出：

```text
以下内容请逐字符原样输出：不要格式化、不要省略、不要补全、不要加注释、
不要改缩进、不要合并行。输出后不要解释。
```

到达绿区后仍然要跑上面三道校验——**别相信任何未经校验的粘贴**。

**终局形态**：绿区已经能 `git pull`，所以代码只走 GitHub；
中转 LLM 从此不碰代码，只传 §2 的那几行结论。
